# R1.1 时间外评价协议与数据准备（2026-11-01）

## 标签结论和证据

原始《附件2-靖戈企业命题材料.pdf》第1–2页明确 num_x、cat_x → y1、时间切分、
横截面 RankIC 再按日平均及输出形状；未提供 y1 的经济含义、预测期限、标签发布延迟。
不能从标签近似均匀分布推出未来收益期限，也不能把 GRU 的 L=10 当作标签期限。
原始材料没有说明数值特征的日内生成时刻。当天全截面输入是赛题接口约定；
将其解释为现实市场某个时刻可交易的信号仍无依据。

已读项目 README、计划、R0报告、数据读取和训练入口。旧 train 缓存的纯结构信息
为 [486,2918)、(2432,5282)，无来源manifest；只用于核对文档，不认证为新实验输入。
本轮未解压 data.z，未打开真实 test 标签；仅对数据包原始字节计算SHA256。

## 固定时间折

所有区间左闭右开，单位为数据时间轴的行，不假设对应具体日历日期。

| 折 | 扩展训练标签 | 隔离区（不用标签） | 外折评价 | GRU末800训练日 |
|---|---|---|---|---|
| F1 | [486,2169) | [2169,2189) | [2189,2432) | [1369,2169) |
| F2 | [486,2412) | [2412,2432) | [2432,2675) | [1612,2412) |
| F3 | [486,2655) | [2655,2675) | [2675,2918) | [1855,2655) |

20行是预先声明的探索缓冲，不是已证实的期限上界。因此默认不能创建声称已排除
期限泄漏的run；调用者必须明确接受 exploratory=True，并将此状态写入结果。
严格认证仍被未知期限阻塞。若获得 horizon=h、额外可用延迟=d，要求 gap>=h+d，
且训练/融合使用标签行 t 必须满足 t+h+d < 拟合时点。

代价：扩展训练各折减少20个标签日，分别剩1683/1926/2169天；GRU保持800天，
整体向前平移20天。无法证明更大的任意有限gap绝对安全，不开展按评价分数挑gap的搜索。
即使隔离标签，历史特征可包含隔离区的已发生X；不能将隔离区标签用于特征、早停或融合。

## 模型选择与融合

- F1没有更早的OOF预测，使用预先固定融合；不能用F1评价标签挑权重。
- F2最多使用F1已成熟的行：[2189,2412)，排除F1最后20行。
- F3可使用完整F1及F2已成熟部分：[2432,2655)。不使用同折或未来折标签。
- 全训练区间训练的旧模型不是OOF，禁止用于初始化新基线；时间折从头训练。
- 外折不得用于early stopping。当前 train_gru.py 仍会对官方valid早停，不能直接
  拿它作为OOF入口。R1.2需要受控runner：冻结训练预算，或先定义带隔离的内层选择。
  本轮登记接口只接受冻结预算（selection_range=None）；未实现内层选择协议。
- 本轮不改变模型默认超参数。既有配置max_epochs的含义与新的选轮策略必须在训练前锁定，
  不能在看见F1结果后选择轮数或seed。
- 首轮seed=42；最多3个事先登记的候选，看到外折分数后协议修改预算为0。
  这两个预算是团队操作约束，不是防恶意用户的全局权限系统。
- 官方valid已经反复用于历史研究，不称为全新留出集；本轮不读取其标签做新选择。

## 缓存及产物身份

R0缓存只支持原始train/valid/test边界，没有任意折、purge和模型来源。因此新增独立
oof模块，不更改R0或旧缓存。接受的输入是已认证来源的训练前缀[0,2918)，严格拒绝
完整数据、官方valid/test行和y2。特征、股票轴、各数组逐行哈希绑定于prefix contract。
逐行哈希避免额外复制整块多GB数组，但会增加顺序扫描耗时。

训练视图的y1/mask_y仅到train_end，并复制以防ndarray.base暴露外折标签；预测视图
不带y1/mask_y。评价标签单独保存，训练runner不得持有评价标签对象。
预测侧可持有到评价终点的X，必须继续使用逐日因果变换；词表/拟合归一化参数只能
从训练视图学习，不能借整段评价特征确定未来类别。这一点需R1.2 runner落实。

命名：

```
outputs/oof_r11/<session>/F1-<run_hash前16位>-s42/
  run.json
  evaluation_labels.npz
  model.pt                 # 或model.txt，由未来runner写入
  model.pt.meta.json
  checkpoint.provenance.json
  evaluation_predictions.npy
  evaluation_predictions.json
```

F2/F3及不同配置使用各自run目录；目录和文件独占创建，不覆盖历史产物。
run绑定数据哈希/轴顺序/边界、完整配置及其哈希、工作区模型代码哈希、seed、软件版本、
purge规则和探索状态。不能只记录Git HEAD，因为大量工作区代码尚未提交。
checkpoint登记验证路径和训练范围，并绑定权重及模型元数据哈希；预测绑定checkpoint、
run、评价区间、分数空间和文件哈希；评价重验整条链，拒绝非有限预测及无定义的每日IC。

来源登记是审计记录，不是对任意复制/伪造权重的密码学训练证明。未来受控runner
必须从新模型初始化起自动生成记录，不能用手工填元数据为旧权重“洗成OOF”。
现有公共接口也不自动限制用户绕开工具读本地文件；它们防止流程中的误用。

## 内存与时间预算

检查时机器总RAM约15.61 GiB，可用约2.51 GiB。按文档形状计算，num_x约7.02 GiB，
cat_x约1.28 GiB，全长21列GRU预处理约1.49 GiB；尚未计标签、掩码和解释器。
整包pickle读取可能同时持有约3.03 GiB压缩数据、约8.5GB解压字节及反序列化数组，
峰值可能约18–24 GiB（估算，不是实测）。当前不能安全直接运行完整加载。

建议后续取得不含官方valid/test标签的受控前缀导出，转成按数组存放的mmap/分块数据；
原始pickle无法靠“训练只用800天”自动实现选择性解码。转换需单独内存预算及授权，
本轮没有通过先加载完整标签再删除来绕过禁止读取测试标签的约束。

F1若仅训练GRU：原有日志单次运行约267–733秒，暂预算5–15分钟/次，包含加载则
预留10–25分钟，未在本机实测。四基础分支串行初跑约30–90分钟，受轮数和存储影响。
按F1终点截断后的原始X仍约5.60 GiB，再加21列缓存约1.00 GiB及运行开销；若先
预计算并释放raw/cat，可降低训练阶段内存。只有低内存数据路径落实后才可承诺16GB可跑。

## R1.2准入结论

R1.1协议与最小工具可以验收；不具备无条件启动真实F1训练的条件。
阻塞：标签期限/可用延迟未知（需官方确认，或明确接受“未认证”的探索模式）、
无已认证训练前缀、当前可用内存不足、尚需受控fold runner并冻结选轮方案。
本轮完成后停在R1.1，不启动训练或超参数搜索。
