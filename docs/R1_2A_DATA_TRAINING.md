# R1.2a：低内存数据与受控时间折入口（2026-11-01）

本轮仅增加独立模块、工具、测试和本报告；不修改 R0/R1.1 文件、配置、训练默认超参数或 Git 索引。
没有竞赛数据训练，没有读取真实测试标签，也没有完整反序列化 data.z。

## 1. 原始包结构：实测和推断分开

低风险检查仅读取外层头尾、最多 1 MiB 压缩前缀，并从 zstd 流取前 256 字节。
用 pickletools 解析有界头部操作码，没有执行 pickle.load/loads。该头部位于 num_x 元数据，未读到数组值或标签。

| 项目 | 观察结果 |
|---|---|
| data.z 大小 | 3,250,274,528 字节，约 3.03 GiB |
| 外层 | pickle protocol 5；BINBYTES 长度 3,250,274,519；7 字节头及 2 字节 memo/STOP 与文件长度吻合 |
| 内层压缩 | zstd magic 28b52ffd；frame content size 9,096,840,663 字节，约 8.47 GiB |
| 解压窗口 | 2,097,152 字节；无 frame checksum |
| 内层序列化头 | pickle protocol 4，字典首项 num_x，NumPy ndarray，shape=(3603,5282,99)，小端 float32 |
| 检查范围外 | 未逐一解析整个 pickle 的其他数组及其字节布局；不能声称已验证整个包可选择性解码 |

src/io.py 现有读取依次 pickle.load 外层压缩 bytes、解压完整 raw、pickle.loads(raw)。
压缩对象约 3.03 GiB、raw 约 8.47 GiB 和反序列化数组可能同时存活，估计峰值 20 GiB 以上，
另有 Python/NumPy/解压临时开销。这是按对象生命周期估算，不是实际峰值测量。

zstd 可按块解压到文件，解压窗口仅 2 MiB；这不代表 pickle 可按行反序列化。
普通 NumPy pickle 会重建 ndarray，并维护 memo/引用关系；流式 Unpickler 仍可能同时保留多 GB 数组。
把解压结果 mmap 后 pickle.loads，也不会自动使其内部 ndarray 成为磁盘映射数组。
针对本包写自定义 pickle 操作码转换器理论上可研究，但本轮有界检查不足以证明其正确性，未实现或冒险使用。

## 2. 推荐存储与转换边界

推荐由数据提供方或有单独授权的高内存环境，导出只包含 [0,2918) 的五个数组：
num_x、cat_x、mask_x、y1、mask_y，以及明确的股票/数值特征/类别特征有序轴。
不得用无来源旧缓存替代，也不得在本轮通过“加载全部测试标签后再删除”绕过限制。
如果只提供位置编号，必须明确记录为原始位置编号，不冒充已知股票代码或特征经济含义。

src/prefix_store.py / scripts/prepare_prefix_store.py 接受已经安全导出的训练前缀 NPY，
分 8 行复制至独占新目录的 NPY，保留 dtype、shape 和原始行/股票/特征顺序。
manifest 最后写入，包含原始包 SHA256、边界、轴顺序、逐数组文件哈希、逐行内容摘要及契约哈希。
原始包 hash 是导出方声明的来源锚点；它本身不能证明导出算法正确。交接还须保留导出程序版本、
源包实算 hash、范围/dtype/shape 清单、逐数组一致性检查结果及操作者授权记录。

PrefixStore 使用 allow_pickle=False、mmap_mode='r'，打开时重验全部文件与内容摘要，
不静默复用旧缓存。F1/F2/F3 共用同一训练前缀，折只创建自己的产物。
验证会扫描整个训练前缀（包括未来外折的训练区间内标签字节），只做完整性校验，
不把这些标签传入模型、选轮或融合。此处“训练前缀”严格排除官方 valid/test 标签。
manifest 与内容共同校验用于防误用/损坏，不是对恶意修改文件的签名或系统级权限隔离。

转换前后验收：原始导出范围必须恰好 [0,2918)，五数组行数一致；逐数组 dtype/shape/值一致，
轴完全一致；不接受 y2 或全长标签。合成数据已覆盖这些行为，真实包转换尚未执行。
映射文件使用完必须 close；异常构造也释放映射，避免 Windows 文件锁。

### 资源与外部转换

- 当前机器总 RAM 实测约 15.61 GiB，本轮查询可用约 3.64 GiB；数值随其他程序变化。
- 普通解包建议至少 32 GiB 机器且有约 24 GiB 可用内存，优先 64 GiB；这是容量预算，须实际监测峰值。
- 预留至少 30 GiB 磁盘（原包、解压中间体、前缀和副本），不要把分页文件当作安全内存方案。
- 高内存机器也不能免除标签访问授权；当前授权不足以运行会反序列化完整标签的转换。
- 本机推荐接收已获授权的训练前缀导出；或在未来单独授权并验证专用跳过标签解析器。
- mmap 解决转换后的按需读取，不证明原始转换峰值安全，也不保证 OS 页缓存不增长。

## 3. 受控训练入口

默认只打印计划，无 store 访问、无训练、无输出目录创建：

```powershell
.\.venv\Scripts\python.exe -B scripts/run_oof_fold.py --fold F1 --model gru
```

F1/F2/F3 统一入口，model 可选 gru/mlp/baseline/hist。真实运行须同时给 --run、--store、
--source-sha256，当前未知期限还须 --accept-unknown-horizon。本轮未执行真实运行命令。
实际路径不调用 src/io.py，也不读取 configs/local.yaml、官方 valid/test 缓存或旧 checkpoint。
配置中的历史 paths 和 eval_split 仅保留为完整配置记录；执行由 runner 控制，不能重定向到旧产物。

融合暂无独立命令行或自动选优；需要评价时应继续遵守 R1.1 不依据本折标签调整规则的约束。

## 5. F1 资源预算与 R1.2b 准入

按形状估算，训练前缀 num_x 为 5.68 GiB（磁盘映射）；F1 21列截面预处理为约 1.00 GiB。
数值+类别前缀及小数组磁盘预算约 7 GiB（类别尺寸参照既有说明，待真实导出核验）。
GRU/MLP 预处理仍分配内存，不是所有特征都 mmap；预测前释放训练预处理，防止两个大面板同时驻留。
若类别 embedding 开启，预测阶段会复制类别面板并按训练词表处理未知类别，这部分也需预算。
树仍需采样后的稠密矩阵：F1最多 1683*800 行，baseline 305列约1.53 GiB，hist 368列约1.85 GiB，
另有 LightGBM 分箱/线程缓冲和原始页缓存。树适配器没有宣称外存训练。

建议四分支串行，禁止并行挤占当前机器。CLI 为神经模型要求可用 RAM >=6 GiB，树 >=10 GiB；
这是保守启动门槛而非峰值保证，R1.2b 必须记录实际峰值并在内存不足时停止。
当前 3.64 GiB 不满足任一门槛，树分支优先放在 32 GiB 环境。
CUDA 不是必需；合成验证使用 CPU，真实 CPU/GPU 性能未测量。

时间预算暂按 GRU 固定8轮预留 30–120 分钟，四分支串行预留 2–6 小时，外加转换、hash扫描和预处理。
这是排程占位估计，不是吞吐实测或完成承诺；R1.1 的旧日志时间不能直接外推固定8轮。
进入 R1.2b 后首先在批准的有限训练片段上计时/测峰值，再给出可用的全量预算。
本轮没有为估计时间而启动真实训练。

结论：代码基础设施已具备合成验证的准入条件，当前不能直接启动真实 F1。
仍需：授权且已核验的训练前缀导出、足够可用内存、明确接受未知期限探索风险；
若要求严格无泄漏认证，还须官方提供标签期限和发布延迟。停在 R1.2a，等待确认。
